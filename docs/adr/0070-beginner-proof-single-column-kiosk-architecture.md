# ADR-0070: 初心者友善單欄聚焦自助導航架構 (Beginner-Proof Single-Column Kiosk Architecture)

## 狀態
已通過 (Accepted)
替代 ADR-0069（雙欄主從時間軸）

## 背景 (Context)
在 ADR-0069 中，我們採用了 Master-Detail 雙欄樹狀時間軸架構。然而，使用者在深入體驗後提出了決定性的回饋：
> 「覺得 不是 很直覺欸」
> 「/grill-with-docs 來找出 最好的呈現 方式 ，連小白 一進來 都可以直接用」

經使用者反饋與互動對齊，診斷出前版架構的核心認知摩擦點：
1. **多重按鈕與滾動干擾（Cognitive Overload）**：
   畫面頂端有 8 顆分類膠囊、年份下拉選單、「全部展開/收合」開關，左側面板又有獨立滾動軸，右側票根也有獨立滾動軸（Dual-scrolling）。初次拜訪的粉絲與一般使用者（小白）無法一眼判定「現在該按哪裡」。
2. **缺乏即時滿足感（Immediate Gratification）**：
   使用者進入網站的心理模型是「想看這場演唱會唱了什麼歌」，而不是先面對複雜的資料庫篩選器與手風琴樹。
3. **不同設備體驗割裂**：
   桌面端雙欄與行動端縱向疊加的操作心智不同，增加維護與認知負擔。

經由 `/grill-with-docs` 的設計對齊，使用者明確拍板採納**「單欄聚焦流 + 兩段式自助導航機（Two-Step Kiosk）」**，讓任何人進入頁面，零學習成本即可立即查閱歌單。

---

## 決策 (Decision)

### 1. 單欄聚焦視圖 (Single-Column Focus Stream)
- 桌面與行動端採用統一的單欄置中版型：
  - 容器寬度設定為 `max-w-[960px] mx-auto`，確保票根排版具備充足呼吸空間，同時避免雙欄過度拉扯視線。
  - **全頁單一垂直滾動軸**：徹底移除左欄獨立滾動面板與雙滾動條困擾，使用者只需自然上下滑動頁面。
  - 頁首提供跳至主內容的無障礙跳過連結（Skip Link）：`<a href="#main-content" class="sr-only focus:not-sr-only ...">跳至主要內容</a>`。

### 2. 即時滿足：首頁直出最新精彩歌單 (Immediate Gratification)
- 網站首次載入時，直接預設選中並渲染髭男最新、最具話題性之大型巡演指標場次（如 `2024 Rejoice 巡演 台北小巨蛋場`）。
- 使用者一進網站，映入眼簾的就是完整、精美的實體演唱會票根與曲目清單，不需要進行任何點擊即可馬上開始享受歌單。

### 3. 四層平鋪折行膠囊導航器 (4-Tier Wrapping Pill Kiosk Selector)
使用者在進一步體驗後明確指示：「不要滑動 就全部顯示」、「需挑分類」、「感覺不用顯示全部 太長了」，因此告別原生表單 `<select>` 下拉框與橫向滑軌，並且**全面拔除「全部分類」與「全部年份」選項**，避免一次性倒出數百個項目造成介面冗長雜亂。導航器預設為最新重大專場（`巡演專場` + `2024`），全面採用自帶官網品牌質感的圓角膠囊按鈕（Pill Chips），自然折行（`flex flex-wrap gap-1.5 sm:gap-2`），短小精悍、畫面一覽無遺：
1. **第一層：選擇演出類型膠囊 (Category Pills)**
   - 平鋪陳列七大官方分類：`[ 巡演專場 (150場) ] [ 特別專場 (7場) ] [ 聯合專場 (7場) ] [ 音樂祭 (32場) ] [ 學園祭 (5場) ] [ 電視演出 (1場) ] [ 線上直播 (2場) ]`。
   - 選中狀態以官網品牌赭金（`bg-band text-band-ink font-bold`）高亮錨定，未選中為白底灰線（`bg-paper text-ink border border-line-soft`）。
2. **第二層：選擇演出年份膠囊 (Year Pills)**
   - 根據當前選取的分類動態提取對應演出年份（如 `[ 2024 ] [ 2023 ] [ 2022 ] ...`），徹底淘汰「全部年份」，每次鎖定具體年份。
   - 全部平鋪折行，點擊年份立即切換當年度演出。
3. **第三層：選擇活動／巡演膠囊 (Tour & Event Pills)**
   - **十個十個分段顯示**：當活動數量超過 10 部（如 2018 年 26 部）時，頂端自動浮現分段按鈕列（`分段：[ 1-10 ] [ 11-20 ] [ 21-26 ]`）。
   - 畫面上任何時候**永遠剛好只顯示 <= 10 顆活動膠囊**，高安定度、高度永遠維持在 2 行以內，徹底杜絕多達 20 幾顆膠囊洗版。
   - 選取活動即時載入預設場次歌單，分段按鈕會自動導航至所選活動所在的頁面。
4. **第四層：切換場次日期膠囊 (Date & City Pills)**
   - **單發活動（全 1 場）直接隱藏**：單場活動點選後直接看歌單，不需多此一舉再選一次。
   - **十個十個分段顯示（> 10 場巡演，如 Editorial 49 場）**：頂端自動提供分段膠囊（`分段：[ 1-10 ] [ 11-20 ] [ 21-30 ] [ 31-40 ] [ 41-49 ]`），任何時候僅顯示該段 10 場，完全不佔大版面，下方歌單秒速映入眼簾！

### 4. 智能自適應兩層分段分頁架構 (Option A: 2-Tier Adaptive Chunking Pagination)
針對包含大量項目的列表（如場地累積排行全 194 處、歌曲次數排行全 89 首），若直接平鋪 20 顆 `[ 1-10 ] ... [ 191-194 ]` 分段按鈕，依然會在行動端折成 4~5 行形成新的按鈕負擔。因此採納使用者拍板之 **Option A 智能自適應兩層分段機制**（`CHUNK_SIZE = 50`, `PAGE_SIZE = 10`）：
1. **少量項目（$\le$ 50 筆，即 $\le$ 5 頁）**：
   - 保持簡潔的單層分段按鈕列（`分段：[ 1-10 ] [ 11-20 ] ...`），按鈕數量固定在 1~5 顆以內，不增加額外點擊負擔。
   - 範例：2018 年活動（26 部）只有 3 顆（`1-10`, `11-20`, `21-26`）；Editorial 巡演（49 場）只有 5 顆（`1-10`, `11-20`, `21-30`, `31-40`, `41-49`）。
2. **大量項目（$>$ 50 筆，即 $>$ 5 頁）**：
   - 自動開啟「大區間層（以 50 筆為一組）」之雙層架構：
     - **第一層（大區間）**：每 50 筆一組（例如 194 處場地拆為 `[ 1-50 ] [ 51-100 ] [ 101-150 ] [ 151-194 ]`，**固定只有 4 顆按鈕**，單行排列）。
     - **第二層（細分頁）**：選中大區間後，展開當前區間內的 5 個 10 筆細分子頁（例如選 `1-50` 顯示 `[ 1-10 ] [ 11-20 ] [ 21-30 ] [ 31-40 ] [ 41-50 ]`，**固定只有 5 顆按鈕**）。
     - **第三層（膠囊內容）**：精準只渲染對應頁次的 10 顆膠囊。
   - **完全自適應狀態同步**：當使用者透過搜尋或 deep hash 錨點跳轉時（例如第 142 處場館），系統自動計算所屬大區間（`101-150`）與細分頁（`141-150`）並雙重高亮，使用者零學習成本。

### 5. 歌曲與場地 Tab 同步落實智能分頁
- **🎵 歌曲 Tab**：
  - 頂部提供平鋪膠囊切換「💿 依發行專輯分類」與「🏆 依演唱次數排行」。
  - **專輯模式**：平鋪歷年專輯膠囊（`[ Rejoice (2024) ] [ Editorial (2021) ] [ Traveler (2019) ] ...`），拔除「全部專輯」，每張專輯精選 10~15 首歌曲膠囊（超過 10 首自動以 10 首分段）。
  - **演唱次數排行模式**：全 89 首歌曲自動啟用兩層分頁（大區間 `[ 1-50 ]` 與 `[ 51-89 ]` 僅 2 顆按鈕；第二層 4~5 顆細分頁），每次精準只展示 10 首，版面極致純淨，點選即更新 `SongSlip`。
- **🏛️ 場地 Tab**：
  - 頂部提供平鋪膠囊切換「📍 依日本地理分區」與「🏆 依累積場次排行」。
  - **分區模式**：平鋪地區膠囊（`[ 海外 ] [ 關東 ] [ 關西 ] ...`），在關東 58 處場館等大型分區中，自動以大區間 `[ 1-50 ]` `[ 51-58 ]` 與細分頁呈現，再也不會被 58 顆場館膠囊佔滿版面！
  - **累積場次排行模式**：全 194 處場館自動啟用大區間 `[ 1-50 ]` `[ 51-100 ]` `[ 101-150 ]` `[ 151-194 ]`，每層永遠只有 4~5 個按鈕，直覺好找不洗版。

### 6. 嚴格遵循 Web Interface Guidelines 規範
1. **動畫安全**：全面替換非預期耗能的 `transition-all`，採用明確的 `transition-colors motion-reduce:transition-none`。
2. **按鈕語意**：全站所有 `<button>` 均顯式宣告 `type="button"`。
3. **無障礙聚焦環**：全面配置 `focus-visible:ring-2 focus-visible:ring-band focus-visible:outline-none`。
4. **數字等寬**：所有場次計數、次數與年份均套用 `tabular-nums font-mono`，防止切換時版面抖動。
5. **表單屬性**：搜尋框配置 `name="q"`、`autoComplete="off"` 與 `spellCheck={false}`。

## 後果 (Consequences)

### 正面影響 (Pros)
- **小白零門檻**：直覺性達到極致，無須說明書，任何人進站都能一秒選巡演、一鍵看歌單。
- **消除滾動迷失**：回歸單一滾動流，不再有雙滾動條拉扯視窗的挫折感。
- **極致行動端體驗**：行動端與桌面端介面高度一致，橫向滑動日期膠囊在手機上操作極其滑順自然。
- **效能提升**：移除大量手風琴樹狀節點與 DOM 元素，初始渲染負擔大幅減輕。

### 相容性與演進 (Compatibility)
- 既有的全域搜尋框（Global SearchBox）完好保留，支援全站任意歌曲、演出、場館之全域模糊直達穿透。
- 歷史 Hash 路由規範（`#/show/:id`、`#/song/:id`、`#/venue/:id`）完全相容且無縫導向對應票根。
