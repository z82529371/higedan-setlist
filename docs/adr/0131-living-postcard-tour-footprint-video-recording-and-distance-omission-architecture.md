# ADR-0131: 參戰足跡動態明信片短片錄製匯出與累計里程廢除架構 (Living Postcard Tour Footprint Video Recording & Distance Omission Architecture)

## Status
已採納 (Accepted)

## Context
在 Issue #56（ADR-0129）原草案中，規劃於個人巡演票夾（`TicketBookFootprintMap`）新增「📸 儲存足跡卡」，並以 540px 靜態 PNG 匯出。然而在深入審視樂迷真實參戰體驗與社群傳播模式（Instagram Stories / Reels / Threads / X）後，發現了兩項關鍵領域認知差距與規格盲點：

1. **「累計遠征距離（~X km）」之領域主體性失真**：
   - 樂團巡演是由隨隊工作人員、巡演車（🚐）與專機（✈️）在相鄰場館間依序串聯位移（如高陽 ➔ 台北 ➔ 大阪）；但**歌迷本人通常是從各自居住地（如台北、東京、香港）單獨出發前往特定演出城市**。
   - 將樂團在巡演時相鄰場次間的累計公路／航線里程（如 `~1450 km`）冠在歌迷身上，既不符合歌迷真實行程，且在物理真實感上容易造成困惑。
2. **靜態圖片在空間軌跡維度上的敘事受限（The Need for Living Video）**：
   - 單場票券（`MemorialCardModal`）與生涯總結卡（`MilestoneCardModal`）適合以靜態單張呈現；但「參戰足跡（Footprint）」的核心魅力在於**「多年來一步步踏遍全日本與海外」的時間積累與移動動能**。
   - 歌迷渴望在社群上分享的，並非僅是一張死板的定格地圖，而是一支**能夠清楚看見自己化身墨鏡歌迷（😎）開車馳騁、沿途將都道府縣逐一發光點亮、最終抵達千秋樂並重重蓋下紀念郵戳的短影片（Living Postcard Video）**。

## Decision

### 1. 全面廢除「累計遠征距離（Distance Omission）」
- 正式從個人票夾參戰足跡明信片與統計模型中廢除「累計遠征距離（~X km）」。
- 底部指標完全回歸歌迷最具自豪感與榮譽感的核心維度：
  - **「🇯🇵 踏破都道府縣（X / 47）」**（含海外城市徽章）
  - **「🎫 參戰總場次」**
  - **「🚩 初陣・最初參戰」** 與 **「🏁 最新參戰」**（含日期、場館與城市）

### 2. 動態明信片票券短片（The Living Postcard Video Architecture）
- 匯出之短影片畫面採標準 540px 復古票券明信片排版（The Living Postcard）：
  - **頂部**：票夾專屬票根編號、持有者暱稱（Holder Name）、參戰歷程年份區間。
  - **中央**：高對比點亮之日本 47 都道府縣金色踩點地圖，墨鏡歌迷（😎）入座自駕車平滑馳騁，路徑即時繪製，途經縣市動態發光點亮。
  - **底部**：踏破都道府縣計數、參戰總場次與初陣／最新戰歷史紀錄。
  - **動態郵戳（Animated Postmark Slam）**：抵達最新場次定格之瞬間，右下角「遠征踏破」紀念雙環郵戳重重蓋下，形成一張完整且極具儀式感的動態票券。

### 3. 巡演倍速連動（1× / 2× / 4×）與「多少就是多少」時長契約
- 模態框內直接整合網站原生之 **`[1×] [2×] [4×]`** 倍速切換器。
- **時長自然連動（Duration-as-Paced）**：尊重歌迷選擇，在所選倍速下動畫播放多長，產生的短片就是多長（「多少就是多少」）。歌迷想細細回味可選 1×，想要緊湊快節奏分享可選 4×。

### 4. 一鍵自動演出錄製與雙軌（Video + PNG）輸出體驗
- **一鍵自動演出錄製（Auto-Record on Click）**：
  - 歌迷點擊「🎬 錄製並下載短片」按鈕。
  - 系統自動將旅程重置回起點，平滑推進並錄製畫面，即時展示微型進度指示（如 `🎬 錄製合成中 65%...`）。
  - 播畢並於郵戳蓋下定格 1 秒後，自動完成封裝並觸發瀏覽器下載 `higedan-footprint-[holder]-[date].mp4`（或 `.webm`）。
  - 錄製完成後，模態框直接切換為內嵌影片播放器供歌迷立即預覽、重播與長按儲存。
- **雙軌輸出架構**：
  - 主按鈕為高對比「🎬 錄製並下載短片（MP4/WebM）」。
  - 副按鈕保留「📸 另存靜態卡（PNG）」，滿足印製紙本或即時發送至通訊軟體之需求。

### 5. 純前端無後端 MediaRecorder 與 Canvas 離線編碼不變式
- 遵循 `ADR-0123` 零後端原則，完全於瀏覽器端透過原生 `HTMLCanvasElement.captureStream` 與 `MediaRecorder` 進行串流錄製與封裝。
- **自適應格式優先權**：
  - 若瀏覽器支援 `video/mp4;codecs=avc1` 或 `video/mp4`（如 iOS Safari 14.8+、Chrome 130+），優先輸出通用度最高之 `.mp4`。
  - 其餘瀏覽器環境回退為 `video/webm`。
  - 在不支援影片編碼的極端或舊版環境，優雅降級為全功能靜態 PNG 匯出並提供友善指引。

## Consequences
- **Positive**: 徹底根除「樂團巡演里程套在歌迷身上」的領域失真，維持資料純粹性與歌迷主體真實性。
- **Positive**: 將空間踏破記憶升格為可直接在 Instagram Reels / Stories / Threads / X 循環播放的「動態明信片短片（Living Postcard）」，極大化社群傳播魅力與情感共鳴。
- **Positive**: 嚴格遵守 `[1×] [2×] [4×]` 速度控制，賦予歌迷自主決定影片節奏的完全自由。
- **Positive**: 兼顧動態短片（主）與靜態圖卡（副），完美覆蓋動態社交與靜態印製場景。
- **Compliance**: 完全遵守 `ADR-0123` 零後端靜態純粹性、`DESIGN.md` 票券設計美學與 PWA 現場離線瀏覽不變式。
