# ADR-0061: 無歌單場次隱藏模式與存根事件架構 (Hidden No-Setlist Mode and Stub Event Architecture)

## Status
Accepted

## Context

1. **歷史演出足跡與歌單情報落差**：
   - 髭男在地下獨立時期（2012～2016 年）曾參與過眾多小型 Livehouse 對バン（聯合演出）、活動嘉賓或商演。
   - 在 LiveFans 等音樂社群資料庫中，部分歷史活動僅記載演出日期、場館與同場樂團，並未有歌迷回報具體演出歌單（曲目數為 0，`setlist: []`）。
2. **兩難困境：全部拋棄 vs 污染首頁**：
   - 若爬蟲完全拋棄無歌單條目，會導致樂團早期的演出歷史足跡在資料庫中永久缺失，無法作為完整的歷年年表。
   - 若無條件納入並呈現在分類與選單中，使用者隨意瀏覽時會頻繁點入「0 首曲目」的空白卡片，嚴重拉低資料庫的訊噪比與瀏覽品質。
3. **巡演專場（Tour）與單發事件（Event）的架構分流**：
   - 巡演專場（`data/tours/`）以共識模板（`templateSetlist`）為骨幹，即使某單一場次現場無即時紀錄，亦可藉由模板與 `diff: {}` 完整推導現場曲目。
   - 單發事件（`data/events/`）各自獨立，無模板可供繼承，需針對其「0 曲目存根（Stub Event）」建立專門的過濾與呈現規範。

---

## Decision

1. **資料管線允許存根建檔並給予提示**：
   - 爬蟲腳本 [`batch-import.mjs`](../../site/scripts/batch-import.mjs) 在匯入單發事件時，若解析出的曲目數量為 0（`pageSongs.length === 0`），允許建立空歌單存根事件（`setlist: []`），同時在終端輸出 `[AUTO-IMPORT NOTICE]`。
   - 資料驗證腳本 [`validate-data.mjs`](../../site/scripts/validate-data.mjs) 將單發事件 0 曲目視為合法存根（Stub Event），輸出 `[Stub Event Notice]` 而非拋出致命錯誤。
2. **前端 UI 預設隱藏模式（`showEmptySetlists = false`）**：
   - 前端首頁預設為嚴選 Setlist 檔案庫模式，**預設不勾選、隱藏無歌單場次**：
     - 若某單發活動旗下所有場次皆無歌單紀錄，預設不計入演出類型（Category）計數與清單。
     - 側邊欄場次抽屜中，預設過濾掉 0 曲目之場次。
3. **提供「顯示無歌單場次」輕量切換開關與虛線邊框膠囊**：
   - 在「場次」查詢頁面的分類控制卡片右上角，提供開關核取方塊：`顯示無歌單場次`。
   - 當使用者勾選開啟時，系統即刻展開所有早期無歌單存根場次：
     - 上方活動膠囊（Unit Pill）未選中時呈現 **虛線邊框 ＋ 柔和字色**（`border-dashed border-line text-muted`），低調提示其為歷史存根；選中時維持正常高亮。
     - 側邊欄場次抽屜之曲目數直接呈現為 `無歌單`。
4. **專屬空歌單情報提示卡（Placeholder Slip）與深層連結支援**：
   - 當使用者選取無歌單場次，或透過外部 URL 錨點（如 `#/show/<id>`）直接訪問時，系統渲染專屬虛線卡片：
     > 「🔍 **歌單情報未明**：本場演出目前尚無公開曲目紀錄」
   - 即使在未勾選顯示模式下，直接透過 URL hash 進入該場次依然能正常顯示該存根與提示卡，且側邊欄抽屜保持選中態，確保不出現破版或空白。
5. **有歌單與無歌單並存活動之行為準則（Mixed Unit Behavior）**：
   - 當單一活動同時包含有歌單與無歌單場次時（如 `A FLOOD OF CIRCUS 大巡業 2018`）：
     - **預設導航落點**：`defaultShowId` 優先定位至「**有歌單的最新場次**」（金澤站），避免使用者點進來先看到空白卡；全活動皆無歌單時才選取最後一場。
     - **活動膠囊樣式**：只要活動內含有 $\ge 1$ 場完整歌單，活動膠囊即維持正常實線按鈕；全活動場次皆為 0 首時才呈現灰底粗虛線按鈕。
     - **頂部跑馬燈計數**：頂部橫幅固定統計該活動真實的總場次數（如 `2 場・7 首歌曲`），忠實反映樂團巡演規模。
     - **場次抽屜過濾**：未勾選時僅列出有歌單場次（金澤 7 首）；勾選後完整展開（金澤 7 首 ＋ 新潟 無歌單）。

---

## Consequences

- 兼顧「歷史演出足跡完整性」與「歌單檔案庫高純度瀏覽體驗」，預設給予使用者 100% 具有歌單的精確資料。
- 介面用詞簡潔克制（僅提示「無歌單」與「本場演出目前尚無公開曲目紀錄」），避免冗餘贅字。
