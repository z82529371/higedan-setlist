# ADR-0062: 歌曲演出列表雙層分類與單元群組化架構 (Two-Layer Song Shows Categorization and Unit Grouping Architecture)

## Status
Accepted

## Context

1. **熱門代表曲演出場次龐大**：
   - 官方髭男dism 的多首代表曲目（例如《Pretender》、《宿命》、《ノーダウト》、《異端なスター》等）在全檔案庫中累積出現超過 80 至 130 場演出。
2. **舊版單列清單之視覺負擔**：
   - 原先歌曲收據詳情卡（`SongSlip`）採用扁平列表，在每一場演出的開頭重複渲染所屬單元與類型標籤（例如 `[Official髭男dism one-man tour 2021-2022 - Editorial - 專場]`）。
   - 在多達數十場的長篇巡迴中，相同的單元標題重複出現幾十次，造成資訊嚴重雜訊與視覺疲勞。
3. **多樣化演出類型缺乏維度過濾**：
   - 演出單元涵蓋七大類型（巡演專場、特別專場、聯合專場、音樂祭、學園祭、電視演出、線上直播）。
   - 使用者想要查找某首歌「在哪些音樂祭唱過」或「在巡演中唱過哪些場次」時，必須在長達上百項的列表中人眼滾動掃描，無法快速切換。

---

## Decision

1. **第一層：類型過濾膠囊列（Category Filter Pills，不設「全部」）**：
   - 在 `SongSlip` 頂部橫幅下方建立橫向分類篩選膠囊：
     - 固定格式：`[巡演專場 (N)] [特別專場 (N)] [音樂祭 (N)] ...`，**不提供「全部」按鈕**以維持精準分類視圖。
     - **動態收合**：僅展示該歌曲「實際出現過（場次計數 $> 0$）」的分類，不展示 0 場次按鈕。
     - 預設選中第一個有效分類（通常為巡演專場）；切換歌曲時自動維持可用分類或回退至首個可用分類。
2. **第二層：按單元分組與素雅收據標頭（Unit Grouping with Understated Subheaders）**：
   - 在選取的分類下，將演出場次依所屬演出單元（`unitId`）進行分組。
   - 每個單元渲染獨立小節區塊（Section）與符合紙質收據氛圍的素雅標頭：
     - **一般低飽和色彩**：取消刺眼之高亮粗邊框，採用沉穩的柔和灰底（`bg-line-soft/40`）與細分隔線（`border-b border-line-dark/30`），搭配素色徽章（`bg-card text-muted border border-line-dark/30`），融入收據純淨視圖。
     - **清晰活動名稱**：採用適度加粗字型（`font-display font-bold text-ink`），清晰標註如 `one-man tour FOUR-RE:ISM` 等單元名稱。
     - **右側場次計數**：標註 `共 N 場`。
   - 單元內的各場次不再重複印製單元標題，僅展示日期、場館、城市、曲目特徵徽章（如 `新歌`、`自彈自唱`、`點歌`）與備註，維持極度清爽之排版。
3. **長篇巡演互動收合機制（Collapsible Long Tours）**：
   - 當單元內場次超過門檻（$> 3$ 場，如大型巡迴及多場次活動）時，自動啟用可收合互動：
     - 標頭變為可點擊切換態，並帶有箭頭符號（`▾` 展開 / `▸` 折疊）。
     - **預設全面折疊**：所有 $> 3$ 場之單元預設全面收合，讓使用者進入頁面時能一覽該歌曲在歷年所有巡演與活動的概覽足跡，免去數十行滾動負擔；$\le 3$ 場之輕量活動則直接保持展開。
     - 頂部提供「全部展開 / 全部收合」快捷按鈕，方便歌迷一鍵縱覽或全局折疊。
4. **場次類型規範化統整**：
   - 於 `site/src/lib/domain.js` 導出 `getUnitTypeLabel(unit)`，統整全站 7 大規範分類名稱，將具備巡演模板之單元統一歸類為「巡演專場」，消解早前資料檔案中部分宣告為「專場」之歷史不一致。

---

## Consequences

- 解決了上百場熱門歌曲列表冗長難讀的問題，去除重複的巡演標題文字。
- 使用者可一鍵依「音樂祭」、「電視演出」、「特別專場」等維度快速過濾，大幅提升歌曲足跡的探索效率。
