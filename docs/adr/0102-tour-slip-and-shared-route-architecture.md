# ADR-0102: 巡演總覽領域實體與雙模切換架構 (Tour Summary Slip and Shared Route Architecture)

## Status
Accepted

## Context

1. **背景與痛點分析**：
   - Official 髭男 dism Setlist 檔案庫在演出檢索維度上，長期以「單場演出票根（`ShowSlip`）」為核心。
   - 在瀏覽大規模篇幅之經典巡迴（如 Major 1st 的 *Hall Travelers*、*Editorial Arena Tour*、2024–2025 的 *Rejoice Arena Tour*、*SHOCKING NUTS TOUR 2022-2023*）時，歌迷面臨以下痛點：
     - **曲目演化與核心架構不可見**：無法一眼洞悉哪些歌曲是這趟巡演 100% 登場的「核心全勤曲」、哪些是雙日連開時交替的「A/B 輪替曲」。
     - **場次限定曲分散**：特定場次加碼的非樣板曲（如橫濱限定曲、千秋樂特別曲、台北點歌）分散在各站 diff 中，缺乏跨場次整合視角。
     - **巡演缺乏專屬深層連結**：社群分享時只能傳送特定單場（`#/show/:id`），缺乏代表整趟巡演的專屬深層連結（`#/tour/:unitId`）。
   - **架構與維護約束**：
     - 底層 `data/tours/*.json` 與 `data/events/*.json` 為爬蟲與資料審查代理人共管資產，禁止改動原始資料結構。
     - 頂層導航需維持行動端乾淨之三維度心智模型（`show` / `song` / `venue`），不得硬塞第四個大 Tab。
     - 視覺需嚴格遵守 `DESIGN.md` 單欄聚焦手帳串流（`max-w-[960px]`）、柔暖牛奶白（`#f8f7f4`）與實體打孔撕裂線擬物風格。

2. **經 Wayfinder (#6) 與決策確認之邊界**：
   - 透過 Wayfinder Map #6 及各項專項決策，確立在既有架構基礎上擴展第四大領域票券視圖——「**巡演總覽（Tour Slip，`TourSlip.jsx`）**」。

## Decision

1. **曲目登場頻率階層與領域計算模型（Decision 1）**：
   - **四級登場頻率語意徽章（登場曲目統計）**：
     - 核心全勤（Core 100%）：`count === totalShows`（徽章：金邊票紙底墨字）。
     - 巡演定番（Regular $\ge 70\%$）：絕大多數場次登場（徽章：深灰邊框票紙底墨字）。
     - 雙日輪替（Rotating $30\% \sim 70\%$）：雙日 A/B 歌單互換曲（徽章：暖金赭邊框票紙底）。
     - 場次限定（Rare / Surprise $< 30\%$）：少數場次驚喜登場之限定曲（徽章：夜紫邊框票紙底）。
   - **短巡演單次孤立曲不變量（Short Tour Invariant）**：
     - 巡演總場次 $\le 4$ 場且登場次數僅 1 次之非模板曲（如 Asia Tour 2024 高陽站的《異端なスター》），即便數學登場率達 $\frac{1}{3} = 33\% \ge 30\%$，領域語意仍精準判定為「場次限定（Surprise）」，杜絕短巡演孤立突發曲誤入輪替。
   - **全勤同款演繹標籤不變量（Monolithic Arrangement Invariant）**：
     - 僅在該巡演 100% 出場次數皆帶有同款演繹時，才於巡演總覽標記 `[點歌]` 或 `[自彈自唱]`（如 Four-re-ism 的《Subtitle》）；若有一場為標準編制則不標（如 Rejoice 的《Pretender》）。全數過濾一手切分字樣（`サビのみ`）與版本字樣（`Rejoice ver.`），回歸節目單純淨排版。
   - **領域純函數封裝**：
     - 於 `site/src/lib/domain.js` 導出純函數 `computeTourStatistics(tourUnitData)`，不侵入底層 JSON，具備完全可測試性。

2. **雙日輪替對稱模型與純淨票券排版（Decision 2）**：
   - **非模板輪替對稱分流（Non-Template Rotating Partitioning）**：
     - 在雙日對稱巡演（如 SHOCKING NUTS 2022-2023）中，非模板插入曲若登場率達 30%～70%（如 Day 2 的 7 首大歌），客觀歸納為 `ROTATING TRACKS // 雙日輪替曲目` 專區，不擠入「場次限定曲」專區，保持限定專區僅收錄真正 $<30\%$ 之稀有曲。
   - **純淨單行票券排版（Pure Ticket Aesthetics Invariant）**：
     - 雙日輪替曲為常態切換曲，規格完全比照主定番歌單，採單行簡約排版（曲名、標籤、`10 / 21 場`），杜絕堆疊多達 70 個重複的「演出場次 `[🎫 ...]`」按鈕；單場票根直達統一代由下方「全國巡演日程足跡」提供。
   - **全國巡演日程足跡（Tour Itinerary）**：
     - 按時序羅列所有巡迴站點、場館與開演時間；超過 10 場預設折疊，提供一鍵展開／收合互動。
     - 卡片對稱標註：`● 定番歌單場 · 全 X 首` vs `▲ 輪替歌單場 · 全 X 首`（若有額外加碼則補充 `◆ 限定：[曲名]`）。

3. **純淨票根美學與外層雙模切換路由（Decision 3）**：
   - **純淨票券（Pure Slip Integrity）**：
     - 票券本體（`ShowSlip` 與 `TourSlip`）回歸純粹實體演唱會門票紙感，嚴禁在票身內部放置 `[⟷]` 模式切換膠囊按鈕；切換職責完整收斂於行動端導航抽屜、桌面端單元選擇列與全域路由。
   - **深層連結與路由狀態機（`#/tour/:unitId`）**：
     - `useArchiveRoute.js` 擴充支援 `#/tour/:unitId` 雙向同步。
     - 完備容錯降級：若 URL 帶入不存在或格式錯誤之 `unitId`，100% 優雅降級回首頁聚光燈（`landing`），杜絕白屏或死循環。

## Consequences

- **正面影響**：
  - **宏觀巡演洞察**：歌迷可從巨觀視角理解每趟巡演的曲目骨架、輪替策劃與場次限定驚喜。
  - **維持架構精簡**：無須異動底層資料庫或爬蟲結構，以純前端領域計算模型達成高度動態統計。
  - **零心智模型混淆**：保持頂層三維度導航（`show` / `song` / `venue`），在 `show` 維度內自然融合單場與總覽。
  - **深層分享賦能**：具備乾淨的 `#/tour/:unitId` 獨立分享深層連結。
  - **極致紙張美學**：票身內部無突兀的工程按鈕，維護擬真票券手帳溫度。

- **邊界與後續演進**：
  - V1 聚焦於 DOM 互動渲染，不包含全票超長 PNG 離屏匯出（避免行動端 Canvas 記憶體溢出，留待 V2 巡演護照卡規格演進）。
