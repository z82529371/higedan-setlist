# ADR-0102: 巡演總覽大票領域實體與雙模切換架構 (Tour Summary Slip and Shared Route Architecture)

## Status
Accepted

## Context

1. **背景與痛點分析**：
   - Official 髭男 dism Setlist 檔案庫在演出檢索維度上，長期以「單場演出票根（`ShowSlip`）」為核心。
   - 在瀏覽大規模篇幅之經典巡迴（如 Major 1st 的 *Hall Travelers*、*Editorial Arena Tour*、2024–2025 的 *Rejoice Arena Tour*）時，歌迷面臨以下痛點：
     - **曲目演化與核心架構不可見**：無法一眼洞悉哪些歌曲是這趟巡演 100% 登場的「核心全勤曲」、哪些是雙日連開時交替的「A/B 輪替曲」。
     - **限定突襲曲分散**：特定場次突襲加碼的非樣板曲（如橫濱限定曲、千秋樂特別曲）分散在各站 diff 中，缺乏跨場次整合視角。
     - **巡演缺乏專屬深層連結**：社群分享時只能傳送特定單場（`#/show/:id`），缺乏代表整趟巡演的專屬深層連結（`#/tour/:unitId`）。
   - **架構與維護約束**：
     - 底層 `data/tours/*.json` 與 `data/events/*.json` 為爬蟲與資料審查代理人共管資產，禁止改動原始資料結構。
     - 頂層導航需維持行動端乾淨之三維度心智模型（`show` / `song` / `venue`），不得硬塞第四個大 Tab。
     - 視覺需嚴格遵守 `DESIGN.md` 單欄聚焦手帳串流（`max-w-[960px]`）、柔暖牛奶白（`#f8f7f4`）與實體打孔撕裂線擬物風格。

2. **經 Wayfinder (#6) 與決策確認之邊界**：
   - 透過 Wayfinder Map #6 及三項專項決策（#7、#8、#9），確立在既有架構基礎上擴展第四大領域票券視圖——「**巡演總覽大票（Tour Summary Slip，`TourSlip.jsx`）**」。

## Decision

1. **出賽頻率階層與領域計算模型（Decision 1 / #7）**：
   - **四級出賽頻率語意徽章**：
     - 核心全勤（Core 100%）：`count === totalShows`（徽章：金邊票紙底墨字）。
     - 巡演定番（Regular $\ge 70\%$）：絕大多數場次登場（徽章：深灰邊框票紙底墨字）。
     - 雙日輪替（Rotating $30\% \sim 70\%$）：雙日 A/B 歌單互換曲（徽章：暖金赭邊框票紙底）。
     - 限定突襲（Rare / Surprise $< 30\%$）：少數場次驚喜加碼（徽章：夜紫邊框票紙底）。
   - **三態突襲與版本歸納**：
     - 原創突襲曲（Surprise Originals）：獨立專區呈現，附帶登場場次直通連結。
     - 特別彈唱／翻唱過場（Interludes & Solos）：序號標記為 `—`，不計入正式曲目累計。
     - 同曲特殊版本（Version Variations）：自彈自唱或站點特別 note 與主曲目合併計算累積次數，附註版本演化標籤。
   - **領域純函數封裝**：
     - 於 `site/src/domain.js` 導出純函數 `computeTourStatistics(tourUnitData)`，不侵入底層 JSON，具備完全可測試性。

2. **連續手帳票券版型（Decision 2 / #8）**：
   - 採「**經典手帳連續票券型（Continuous Slip Flow）**」單欄架構：
     - **巡演票頭**：全名、起訖時間、站點總數、跨都道府縣規模徽章、影音收錄標註。
     - **共識母單區塊**：帶有四級頻率膠囊徽章之標準歌單序列。
     - **驚喜插入專區**：獨立羅列非樣板曲目及所屬演出場次。
     - **直式全國日程足跡表**：按時序羅列所有巡迴站點、場館與開演時間；超過 10 場預設折疊，提供一鍵展開／收合互動，每站皆可點擊直達單場票根。
     - **實體打孔線與條碼頁尾**：複用 `TicketPerforationDivider` 與 `TicketBarcodeFooter`，保持一致的手帳溫度。

3. **雙模切換互動與 URL 雙向路由架構（Decision 3 / #9）**：
   - **票券頂部微型分段開關**：
     - 於票券頂部提供即時切換膠囊：`[ 📜 巡演總覽大票 ]` ⟷ `[ 🎫 單場即時票根 ]`。
     - 點選巡演單元預設開啟總覽大票；點選特定單場或外部帶有場次 Hash 則直達單場票根。
   - **深層連結與路由狀態機（`#/tour/:unitId`）**：
     - `useArchiveRoute.js` 擴充支援 `#/tour/:unitId` 雙向同步。
     - 完備容錯降級：若 URL 帶入不存在或格式錯誤之 `unitId`，100% 優雅降級回首頁聚光燈（`landing`），杜絕白屏或死循環。

## Consequences

- **正面影響**：
  - **宏觀巡演洞察**：歌迷可從巨觀視角理解每趟巡演的曲目骨架、輪替策劃與突襲驚喜。
  - **維持架構精簡**：無須異動底層資料庫或爬蟲結構，以純前端領域計算模型達成高度動態統計。
  - **零心智模型混淆**：保持頂層三維度導航（`show` / `song` / `venue`），在 `show` 維度內自然融合單場與總覽。
  - **深層分享賦能**：具備乾淨的 `#/tour/:unitId` 獨立分享深層連結。

- **邊界與後續演進**：
  - V1 聚焦於 DOM 互動渲染，不包含全票超長 PNG 離屏匯出（避免行動端 Canvas 記憶體溢出，留待 V2 巡演護照卡規格演進）。
