# ADR-0128: 巡演票券路線圖與個人票夾參戰足跡整合及場館定位郵戳收斂架構 (TourSlip Route Map & Ticket Book Footprint Integration with Venue Mini Locator Stamp Omission Architecture)

## Status
已採納 (Accepted)

## Context
在 ADR-0124 中，系統建立了 `<VenueMapCanvas />` 雙層座標聚合、SVG 列島雙副聯底圖與 `buildJourneySequence` 巡演移動序列純函式，並於 ADR-0125 / ADR-0126 / ADR-0127 將全生涯巡演足跡確立為獨立頁面與行動端極大化畫布。

依據 ADR-0124 之規劃，地圖引擎需進一步貫通至其餘核心介面（巡演總覽票券 `TourSlip.jsx`、個人巡演票夾 `TicketBookPage.jsx` 與單一場館票券 `VenueSlip.jsx`）。然而在實作整合與體驗審查時，面臨以下架構取捨：

1. **巡演票券（TourSlip）時序列表與空間路線的檢視衝突**：
   - 歌迷查閱巡演總覽票券時，時序日程表（按開演日期、城市、開場開演時間排列之清單）是快速檢索與跳轉單場票根的首要依據；若強制將大型地圖插入日程表上方或取代日程表，將大幅拉長垂直滾動距離，破壞票券閱讀節奏。
2. **非實體場次對巡演路線實體終點的干擾**：
   - 部分巡演尾端包含線上直播場次（例如 `14-2021-editorial` 於 47 場實體公演後，於 `2022-05-01` 舉辦線上配信收官公演）。巡演路線圖必須精準辨識「最終實體站（`2022-04-17` 松江凱旋場）」，避免跨海虛擬漂移，並妥善標記線上配信場。
3. **個人巡演票夾（TicketBookPage）的參戰足跡踏破可視化與資訊密度膨脹**：
   - 歌迷在票夾打卡現場演出後，需要直觀了解個人的「日本 47 都道府縣踏破進度」與個人參戰空間軌跡。但個人足跡不同於巡演動畫，初次載入時歌迷期望直接看見「已完成的歷史足跡全景」，而非每次都從最初場次緩慢重播；同時，隨著打卡場次累積，生涯里程碑區塊垂直長度劇增，必須具備靈活的空間收納機制。
4. **單一場館票券（VenueSlip）微型定位郵戳地圖（Mini Locator Stamp）的體驗冗餘與負擔**：
   - ADR-0124 Decision 4.3 原構想於 `VenueSlip.jsx` 票頭嵌入微型定位地圖。但在實際視覺與排版審查後發現：在僅有一座場館的票根頭部放入極小尺寸地圖既無法展示有效的區域空間脈絡，又造成票頭資訊嚴重過載與視覺焦點分散；且票券工具列已具備高清晰度之 Google Maps 外部導航連結。

## Decision
確立巡演路線圖、個人票夾足跡踏破地圖之雙向整合契約，並正式廢除場館微型定位郵戳地圖：

1. **TourSlip 巡演路線圖面板（`TourJourneyMapPanel`）與日程雙模式切換**：
   - 於巡演總覽票券之「全國巡演日程足跡」區塊頂部提供分段切換按鈕：**`📋 時序日程表`（預設）** 與 **`🗺️ 巡演路線圖`**。
   - 路線圖面板頂部提供路線狀態摘要條（`tour-journey-info-bar`）：
     - 清晰標示「首站（START）」與「終點（FINAL）」之演出日期與場館名稱。
     - 統計陸路（🚐）、航線（✈️）、同館連日駐留（🏕️）次數與累計估算移動里程（`~X km`）。
     - 若巡演包含線上配信場次（`isVirtual: true`），物理路線終點精準停留在最後一場實體公演，並於資訊列下方獨立展開「📡 線上配信場 (n)」高對比徽章。
   - 地圖畫布內之站點釘點（`journey-stop-marker`）與左下角 HUD 之「SETLIST ➔」均可直接點擊直達該場單場票根（`ShowSlip`）；地圖組件預留 `animalAnimationProps`（含 stops 與 transitions 序列），無縫支援下一階段「四位團員吉祥物隨行移動動畫」。
2. **TicketBookPage 個人參戰足跡踏破地圖（`TicketBookFootprintMap`）與里程碑全尺寸折疊**：
   - 於個人巡演票夾之生涯里程碑區新增「🗺️ 我的參戰足跡地圖」：
     - **實體場次純淨過濾**：自動過濾線上直播與虛擬場次，僅納入具有實體場館之現場打卡記錄。
     - **踏破進度條與海外統計**：即時計算日本 47 都道府縣踏破進度（如 `已踏破 2 / 47 都道府縣` ＋ 進度百分比進度條），若有海外參戰場次則獨立標註 `+ N 海外城市`。
     - **歷史足跡全景呈現契約（`initialProgress: "end"`）**：不同於巡演從起點出發之循序探索模式，個人足跡地圖初始化時直接以「完成態」渲染歌迷已打卡的所有歷史路徑（`data-leg-state="footprint"`），單一編號圓圈鎖定最新參戰場次，並支援點擊站點檢視單場票根。
     - **里程碑三大區塊全尺寸獨立折疊**：Top 3 現場神曲（`toggle-top-songs-btn`）、參戰時間軸（`toggle-timeline-btn`）與足跡地圖（`toggle-footprint-map-btn`）均配備獨立之折疊按鈕與箭頭指示器（預設展開），兼顧資料豐富度與版面整潔。
3. **VenueSlip 微型定位郵戳地圖之收斂與正式廢除（Deprecation & Omission）**：
   - 正式廢除 ADR-0124 Decision 4.3 中於 `VenueSlip.jsx` 嵌入微型定位郵戳地圖之提案。
   - `VenueSlip.jsx` 維持極簡高密度單行票根風格標題：`場館標題（縣市・城市）`、`原名副標題` 與 `舉辦場次總結`，地理導航完全由工具列既有的 Google Maps 外部連結以及全國場地導航地圖（`VenueNavigator`）承擔，避免票頭卡片化與視覺噪音。
4. **多語系在地化與 SSR 測試守護**：
   - 補齊 `zh-TW`、`ja`、`en`、`ko` 四國語言字典鍵（包含日程/路線切換、交通工具分類、線上配信、踏破進度等）。
   - 於 `site/tests/ui/venue-map-slips-integration.test.js` 建立端到端 SSR 測試，嚴格驗證 TourSlip 雙模式切換、線上場次隔離、TicketBook 47 都道府縣踏破計算、里程碑折疊開關，以及 VenueSlip 零微型郵戳之乾淨票頭不變式。

## Consequences
- **Positive**: 完美貫通 `<VenueMapCanvas />` 於巡演票券與個人票夾之深度整合，補齊地理與空間敘事拼圖。
- **Positive**: 巡演路線圖保留時序日程表為預設，兼顧極速查閱與空間視覺化，且精準處理線上配信場。
- **Positive**: 個人票夾以「全足跡呈現」符合歌迷回顧戰果之心理模型，折疊機制確保大量打卡下依然輕快。
- **Positive**: 果斷捨棄 VenueSlip 冗餘微型地圖，維持單一高密度票根美學，避免過度設計。
